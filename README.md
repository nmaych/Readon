# Readon

一个简洁的 Android 阅读器。书籍来自 GitHub 仓库，在线阅读或下载到本地，界面遵循「主页 / 书架 / 设置」三栏结构。

当前版本 **1.0.3**（versionCode 10003）。

## 功能

### 主页 —— 在线书库
- 从 GitHub 仓库递归列出所有可读文件，按文件夹自动分类（如 `默认/xxx.txt`）
- 支持格式：`txt`、`md`（及 `markdown` 别名）、`html`、`epub`；`pdf` 提示下载后用系统应用打开
- **在线阅读**：点书即读，无需下载，正文先流式落盘再分页排版
- **下载**：点右侧下载图标保存到设备，带百分比进度，出现在书架；下载在应用级作用域运行，**切到书架或设置也不会中断**
- 书库列表在应用级缓存：切换标签页不会重新拉取，只有仓库 / 分支 / 令牌 / 线路改变或手动刷新时才会重新获取
- 搜索书名 / 分类；顶栏显示当前仓库与分支；可配置访问令牌以提升 API 限额

### 书架
- 本地已下载书籍的封面网格，封面按书名哈希生成渐变，同一本书永远同一张封面
- 阅读进度百分比直接画在封面上；从阅读器返回或下载完成时自动刷新
- 每本书显示已读章节数与上次阅读时间（`12/340 章`、`上次阅读：今天 14:30`）。章节总数由阅读器在建目录时记录，书架不必为此重新解码整本书；从未打开过的书不显示这两项，而不是显示 `0/0` 或 1970 年
- **从本地导入**：右上角「+」一次可选多个文件，导入 `txt` / `md` / `html` / `epub`。文件流式复制进应用存储，大文件不会占用整块内存；多选导入在应用级作用域运行，切换页面不会中断
- 排序：最近阅读 / 最近添加 / 书名 / 分类；长按删除

### 阅读器
- 正文用 Compose 原生排版，所见即所量：分页与渲染同一套测量
- 加载时显示当前阶段（连接线路 / 下载进度 / 排版），失败会说明原因并可重试或返回，不会停在「正在排版」
- 左 1/3 屏上一页，右 1/3 屏下一页，中间点按呼出/隐藏工具栏
- 自动识别章节（`第X章`、`Chapter N`、`楔子/序章/尾声`、Markdown 标题），侧滑目录直达
- 全书全文搜索，逐条跳转
- 阅读主题：纸白 / 米黄 / 护眼 / 夜间 / 纯黑；字号 12–30sp；行距 1.2–2.4；衬线开关
- 阅读位置以字符偏移保存，改字号后仍停在同一句话
- TXT 自动检测编码（UTF-8 / GBK / UTF-16，含无 BOM 情况），采样会同时看文件头部与中段，避免「ASCII 开头 + GBK 正文」被误判为 UTF-8
- 翻页按需分页，整书不预排版，百万字也秒开

### 设置
- 阅读偏好（主题、字号、行距、字体、屏幕常亮）
- 应用主题：跟随系统 / 浅色 / 深色
- 书库来源：GitHub 用户名 / 仓库 / 分支 / 访问令牌，全部可改
- **网络线路**：显示当前实际生效的线路，可手动指定，可点「检测线路」逐条测试
- 存储：查看占用、清空本地书籍
- 更新：从 GitHub 检查新版本，下载并校验 SHA-256 后安装。检查在应用级作用域运行，切换标签页不会中断或重来；失败不会记入「上次检查」，因此网络恢复后可以立刻重试
- 关于：版本信息

## 网络线路

`raw.githubusercontent.com` 在部分网络下被完全阻断（连接超时后 TLS 重置）。因此所有请求都同时向多条线路发起，取最先成功的，并记住可用线路。

| 线路 | 小文件 | 大文件（>20 MB） | 列表接口 |
|------|--------|------------------|----------|
| GitHub 直连 | 超时 | 超时 | 可用 |
| cdn.jsdelivr.net | 可用 | 403 | 403 |
| fastly / gcore.jsdelivr.net | 可用 | 403 | 403 |
| ghproxy.net | 可用 | 可用 | 403 |
| gh-proxy.com | 可用 | 可用 | 可用 |
| ghfast.top / gitmirror / Statically | 超时 | 超时 | — |

实测数据来自本仓库（53 本书，33 本超过 8 MB，最大 75 MB）。jsDelivr 限制单文件 20 MB、整包 50 MB，所以它无法覆盖这个书库；`ghproxy.net` 与 `gh-proxy.com` 才能。

因此：
- **列表**与**取文件**用两套独立的线路表——`api.github.com` 与 `raw.githubusercontent.com` 是两个不同的服务，前者没被阻断时后者可能已被阻断。
- 选线路先用 **2 KB 的 Range 请求探测**，再流式传输，避免把几十兆的文件在九条线路上各试一遍。上次成功的线路会被**单独先探一次**，所以网络正常时每次打开书只有一个 2 KB 请求，而不是每次都跑九条线路。
- 探测和竞速的请求都是**可取消**的：选出赢家后，其余请求立即断开，不会留下十几条连接空等到超时。小请求（列表、清单、探测）用 8–25 秒的整调用超时，大文件传输用 10 分钟——「线路没反应」应当很快变成一条能读的错误，而不是让界面一直转圈。
- 在线阅读的文本会**先流式写入缓存文件再解码**，因此峰值内存只有一个字符缓冲；在线阅读上限 64 MB，超过的书提示先下载（下载直接流式写盘，不进内存）。

## 书库格式

任意公开 GitHub 仓库，文件夹即分类：

```
仓库根/
├── 默认/
│   ├── 书名.txt
│   └── 另一本书.epub
├── 科幻/
│   └── 三体.txt
└── ...
```

默认书库：`nmaych/ReadonBooklibrary`，分支 `main`。全部可在设置中修改。

## 构建

需要 JDK 17、Android SDK 34、Gradle 8.7。依赖已全部落在本地 Gradle 缓存中，支持离线构建：

```
build.cmd                # assembleDebug
build.cmd assembleRelease
```

发布前运行仓库自检：

```
check.cmd                        # 工作流、版本号、清单、.gitignore、书籍逻辑
tools\check-book-logic.cmd       # 编码检测、章节切分、分页与书架标签（桌面运行，无需设备）
tools\verify_release.py          # 校验 dist/ 里的 APK 与清单是否自洽
```

`tools\check-book-logic.cmd` 直接编译 `TextCodec.kt`、`Chapters.kt`、`PageCursor.kt`、
`Model.kt` 与 `ShelfLabels.kt` 这几个纯 JVM 文件（不复制源码，避免与线上代码脱节），
覆盖 UTF-8/GBK/UTF-16、BOM、「ASCII 开头 + GBK 正文」这类会导致乱码的边界，章节切分
的连续性与性能，分页游标的「第一页不能对着空列表取 last」回归，以及书架标签的
「昨天是日历天而不是 24 小时」等日期边界。离线 Gradle 缓存中没有 JUnit jar，所以这些
检查放在这里而不是单元测试里。

`PageCursor` 之所以从 `Paginator` 里拆出来，正是为了让这条检查能覆盖它：1.0.2 打开
任何一本书都闪退，根因就是分页器用空列表取 `last()`，而那段代码在 Compose 的
`remember { ... }` 里，加载器的 `try`/`catch` 包不到它。

发布版签名密钥位于 `keystore/readon-release.jks`，凭据在 `app-project/keystore.properties`（不入库）。

发布新版时改 `app/build.gradle.kts` 里的 `appVersionCode` / `appVersionName`，构建后：

```
build.cmd assembleRelease
copy app-project\app\build\outputs\apk\release\app-release.apk dist\readon-1.0.3.apk
python tools\ci_release.py --name 1.0.3 --apk dist\readon-1.0.3.apk
python tools\verify_release.py
```

`ci_release.py` 会用实际产出的 APK 重算 SHA-256、写好下载地址，并从 CHANGELOG
提取该版本的说明写入 `dist/update.json`——手改哈希会让应用判定更新包损坏，手改
说明则会让 GitHub release 页面和应用内提示不一致。`verify_release.py` 独立复算
一遍（不 import 发布脚本），确认哈希、版本号算术、下载地址和说明都对得上。

## 更新机制

1. 应用内「设置 → 更新」读取 `dist/update.json`（走多线路）
2. `versionCode` 高于当前版本即提示；比对始终用 versionCode，不用版本名字符串
3. 下载到应用私有缓存，逐块回传进度；有 `sha256` 则校验，不匹配直接删除
4. 调系统 PackageInstaller 安装；首次需要用户在系统里授予「安装未知应用」权限

## 图标

`art/original-icon.png` 是设计原图，不重绘。`tools/make_icon.py` 只做派生：各密度 PNG、圆形版本，以及自适应图标前景（背景取原图自身的深蓝色，因此任何启动器裁切形状下都不会露出白边）。
